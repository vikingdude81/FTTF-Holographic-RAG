Corpus: theology-philosophy-archive, 101 docs (40 chats, 38 topics, 21 papers/drafts incl. 4 PDFs).
Gold: 24 queries, gold sets derived from the archive's verified link graph (`bench/gold.json`); types: semantic paraphrase, exact identifier, multi-hop.
Harness: `bench/archive_bench.py`; raw results `bench/results_2026-10-27.json`.

## Setup audit (before anything ran)

1. **Environment drift**: repo had no venv; Ollama installed but not serving. Fixed: uv venv + `pip install -e .`; `ollama serve` (nomic-embed-text present). 117/117 tests pass.
2. **Packaging gap**: the `ollama` python client is required at runtime (chromadb's Ollama embedding function) but is not declared in pyproject — a fresh install crashes on first ingest with `ValueError: The ollama python package is not installed`. Add it as a dependency.
3. **Embedding window**: nomic-embed-text via Ollama is hard-capped at 2048 tokens. `--max-chars 12000` is silently clipped (~4-5k chars effective: cos(stored, head3800)=0.97; >6k input errors). The default `max_chars=2000` is well matched to the real limit; long-doc tails are invisible to vector ranking but visible to BM25 (which indexes the stored text). Fix path: chunk-level embeddings — `chunker.py` exists but feeds only the hologram, not the Chroma doc embedding.
4. **Architecture, verified**: Stage-1 hologram (10kD) performs **project routing only**; Stage-2 file ranking is raw 768D cosine. With a single project, FTTF ≈ dense vector RAG — the bench confirms this (0.687 vs 0.626 MRR). The holographic value proposition is a many-projects routing problem (Ai_Command_Center scale), not a corpus-size problem.
5. README features verified present in code: orthogonalized keys, 4-bank binding, CORVACS-lite saturation, hit-based promotion, HMAC cache, cache auto-invalidation on ingest.

## Findings

1. **Hybrid fusion is the product.** 24/24 golds in top-5, MRR +0.18 over either component alone. Vector+lexical on this corpus beats each alone; alpha default (0.5) untouched.
2. **Hologram adds routing, not ranking** — at 100 docs/1 project it neither helps nor hurts ranking materially. The *real* FTTF claim (project-level addressing at scale) is not yet benchmarked; next bench should be multi-project.
3. **BM25's tail visibility** inflates its numbers on long docs; a chunk-embedded dense baseline would likely beat it.
4. **Caveats:** n=24; gold author = corpus author (paraphrased queries mitigate, blind queries should be added next round); single corpus; one embedding model.

## Incident note (audit trail)

The **first run of this bench was invalid**: an archive-side batch frontmatter script had gutted 27 chat files (to 37 bytes) and clipped head sections of 22 topic files. The bench caught it — a query about `b_t = (theta_t, m_t)` returned nothing, and probing showed a 37-byte "doc". Archive restored from git (`cf6883b^`), lint hardened with a TINY-file check; bench rebuilt clean (numbers above are the restored-corpus run; the earlier invalid results file was overwritten). This is the cross-repo audit loop working: a retrieval bench found a data-integrity bug that the archive's own lint had missed.
